Secure Video Access
The problem

Hospitals need surgical videos. Sharing them has to be secure, approved, and short-lived.

A healthcare client needs to share very large procedure videos with doctors and IT staff at outside hospitals. The files contain patient information, so every share must meet HIPAA requirements. The client wants a solution soon, with as little to run as possible.

🏥

Who needs the files

Staff at outside hospitals. They don't have accounts with the client and shouldn't need a Google account.

📦

What they're downloading

Procedure videos, typically hundreds of gigabytes and sometimes over a terabyte per request.

🧑‍💼

Who decides

A small team at the client receives each request, checks it, and approves or declines it.

Constraints

It's urgent. The client wants something working soon, so reusing proven pieces matters.

Minimal infrastructure. The client would rather not run servers. We weigh every option against this.

Our recommendation

SFTPGo on Google Cloud

It's the only option that checks every requirement today: data stays in the client's cloud, password + MFA sign-in, approval and expiry built in, and reliable resume for very large files. It's also already built as a working proof of concept, which helps with the urgency.

The trade-off: the client runs a small amount of infrastructure. Google-managed Kubernetes (GKE Autopilot) and a managed database keep that light.

Strong alternative

Serverless portal

If "no infrastructure at all" turns out to be a hard line, this is the Google-native fallback. Hospital users sign in with password + MFA and download directly from Cloud Storage using short-lived links. There are no servers, and most of the proof-of-concept pieces carry over.

The trade-off: for terabyte-scale files, hospitals should use a download manager rather than a plain browser.

Why it meets HIPAA
  • One BAA: every service that touches the videos is a Google Cloud service under the client's BAA
  • Strong sign-in: password + authenticator code for hospital users, company sign-in + MFA for staff
  • Encrypted: in transit (SFTP / HTTPS), and at rest with a separate key per hospital
  • Minimum access: each user sees only their approved files, read-only
  • Automatic expiry: sign-in stops and copies are deleted when the window ends
  • Audit trail: every request, approval, sign-in and download is kept for 6 years

HIPAA is a shared responsibility: Google secures the infrastructure, the solution enforces the safeguards, and the client keeps its policies and reviews in place.

Why SFTPGo
  • Supports both password + MFA and SFTP, which no fully managed Google option offers today
  • Resumes large downloads exactly where they stopped
  • Works with tools hospital IT already uses (Cyberduck, WinSCP), plus a browser option
  • Reads directly from Cloud Storage, with no file servers or copies on disk
  • Locks each account to one folder, the hospital's network, and an end date
  • Open source, with an Enterprise edition for commercial support

Security controls at a glance
  • Accounts start switched off; files are copied only at approval, into a folder for that request alone
  • Hospital access only from approved networks, checked at Google's edge and again on the account
  • The review console is never exposed publicly; it reaches SFTPGo over a private network
  • No passwords or keys stored in code; workloads use short-lived Google credentials
  • Revoke in one click, or switch off a hospital's key to cut off its files instantly
